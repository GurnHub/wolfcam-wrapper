**Alpha release.** Second build of WolfDeck. It fixes the Config view going blank, keeps the Frag finder's state, and adds the fixes and features made since 0.1.0-alpha.1. Bug reports are welcome as GitHub issues.

WolfDeck is a desktop front end for [WolfcamQL](https://github.com/brugal/wolfcamql), the Quake Live / Quake 3 demo player, and a replacement for Wolf Whisperer. It does not include WolfcamQL; it starts the copy you already have.

## Fixed

- **The window went blank after clicking a toggle in Config.** The app had not crashed: the whole page scrolled out of the window. The hidden checkbox behind each toggle was positioned against the page, so after the list had been scrolled, clicking a toggle focused a checkbox below the window and the page scrolled to show it. The checkbox now stays inside its toggle, and the page itself can no longer scroll.
- **The Frag finder lost its form and results** whenever a result was played or you left the view. The filters, results, ticked rows and list position now stay as they were, and the filters are remembered after a restart. A **Reset** button clears them.
- **Renders hung forever** when a clip ran past the end of its demo. Clips are now clamped to the end of the demo, and a capture that makes no progress for 5 minutes stops with an error.
- **Render output from one clip could be taken for another's** (`kill` matched `kill-2.avi`), so its files were deleted or spliced into the wrong encode.
- Two clips with similar names could write the same file, and an unnamed clip was saved as `-2`.
- Renaming a demo with a different extension removed it from the library.
- Image-sequence renders sent every frame file to the UI.
- Settings re-checked the install on every keystroke and could show an out-of-date result.
- In the Player, Space also pressed the last clicked button, the position could run past the end of the demo, and marks were stored as fractions.

## New

- **Error screen instead of a blank window.** If a view fails, it shows the error with **Try again** and **Copy error** while the rest of the app keeps working. The error is also saved to `last-error.json` in WolfDeck's data folder, so please attach it to bug reports.
- **Slow motion and extra commands per clip** in Clips & render.
- **Encode while recording** through WolfcamQL's ffmpeg pipe, without writing an AVI to disk first.
- **Missing maps:** the Library marks demos whose map WolfcamQL cannot load, and has a filter for them. A SteamCMD setting lets WolfcamQL download Steam Workshop maps itself.
- **Player:** go to a game clock time, jump to the previous or next round. Record video now pauses along with the demo.

## Download

| System | File |
| --- | --- |
| Windows 10/11 | `WolfDeck_0.1.0_x64-setup.exe` |
| Linux | `WolfDeck_0.1.0_amd64.AppImage`, or `WolfDeck_0.1.0_amd64.deb` for Debian/Ubuntu |

`SHA256SUMS.txt` lists the checksums. Inside the app the version still shows as 0.1.0. Installing over 0.1.0-alpha.1 keeps your settings, profiles and clips.

The Windows installer is not code-signed, so SmartScreen may say "Windows protected your PC". Choose *More info*, then *Run anyway*.

WolfDeck supports Windows and Linux only; there is no macOS build.

## Requirements

- WolfcamQL 12 or newer, with the Quake Live pak files in its `baseq3` (WolfDeck can copy them from your Quake Live install).
- ffmpeg, only for encoding renders to MP4/MOV/MKV.

## Not yet verified

- **Live control on Windows.** The Player's buttons reach WolfcamQL through a key press (F13 by default, changeable in Settings). This has not been tested on a real Windows machine yet. Launching demos and batch rendering do not depend on it.
- **The blank-window fix on Windows itself.** It was checked in Chromium, the engine behind the Windows webview, but not in the Windows app.
- **`.dm_90` / `.dm_91` demos** are decoded according to the WolfcamQL source, but no sample files were available for testing. Please report any demo that shows as unreadable.
